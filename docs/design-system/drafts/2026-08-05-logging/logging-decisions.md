# Workout Logging — decisions log

Round 1 review, logging screen. Charter constraints held throughout: two hues (dusty blue = now, moss = earned), no glow, no third hue, one-tap logging sacred.

## Status legend used in the explorations file

Every option in `Logging Row Explorations.dc.html` carries a stamp. **Locked** = the decision that stands. **Rejected** = considered and turned down, reason recorded below. **Superseded** = it was right at the time and a later turn replaced it (early full-screen compositions, and treatments that later turns refined). **Fallback** = not chosen, but the option we drop back to if the winner fails.

**Precedence rule: the highest turn number wins.** Where two options are stamped Locked about the same thing, the later one is the current answer and the earlier one is history that has not been restamped. This table is the single source of truth, and it always reflects the latest decision; build from it rather than from an early Locked stamp. Examples already in play: 21d's single subheader line supersedes the two line target and ghost from 8a, 18b's semantic column grid supersedes 14e's positional one, and the rest countdown in the card supersedes 1d's rest in the seam.

Two stamps were inferred from the turn intros rather than recorded here by id, and are worth a second look: `9a` is stamped Locked · A2, since 9a's own body names A2 (a 38px translucent glass circle, blur behind, no hard border) as the lean and turn 10's intro records the glass circle ⋯ as locked — that is the treatment the Header nav row describes. The same-turn losers in 10, 11, 13, 14, 16 and 17 are marked rejected on the basis that those turns each resolved to one winner.

## Open

- **Moss completion moment is a transition, not a state.** Tapping the armed Finish button gives roughly a 250ms moss confirm on the button, then pushes the summary screen immediately. The persistent "complete" row in the assembly demo is a demo affordance so the state can be inspected; it must not linger in the real app. The earned-moss payoff belongs to the summary screen.

### Known gaps on this screen, deliberately deferred

- Swap sheet: entry point is locked, the picker itself is not designed. Lives adjacent to this screen, so it is the natural next piece after the column variants.
- Detail: the rail's Detail button links out to the exercise's own page. Not designed here, deliberately: that page already exists as a destination from the progress screen, where you tap an exercise to see progression over time, recent sessions, and resources. It is one page with two entry points, not a logging screen feature, so designing it from inside the logging flow would have produced a second version of a screen that already has a home. Logging only owes it a link.
- Active superset logging: locked as 19a. Live in `Superset Demo.dc.html`.
- Skipping an exercise outright, and reopening an exercise after it has been rated. Resolved in 22 and 24.
- Rest visibility when the active card is scrolled off screen: resolved in 25b, nothing on screen.
- First-exercise and empty states: resolved in 25d and 25e.

- **19a vs 19d presentation** — resolved in favour of 19a. 19d (one card, member rows, open member as a lighter band with brighter hairlines and a 16px name) was preferred collapsed, but open it read as a worse version of the card it replaced: same content, weaker separation, contrast re-invented that the card already supplied. 9d needs no revision. Measured for the record: 19a swung ~266px of height through a round, 19d ~240px, which was not worth two card anatomies.

- **Warm-up access** — iOS-style glass back button (‹, top-left) vs in the ⋯ popover. Leaning back button: the menu is cleaner but unintuitive, and warm-up is genuinely the previous step in the flow.

## Deferred / to build

- Repeated swaps: if the same substitution happens several sessions running, the program editor should offer to make it permanent. Out of scope for logging.
- Timed exercises: whether the running timer needs to survive leaving the card.
- 15b's value switcher is rejected for now, but the readout idea may return if a third value ever appears in a sheet.
- 16b (reason first) is rejected: better suggestions, but it makes you diagnose your own motives before seeing a single exercise. Its four sentences became 17a's four chips.
- The `est` marker on a swapped load is rejected. There is no defensible way to estimate a load for an exercise with no history, and a wrong printed number costs more trust than an empty cell costs convenience. Percentage prescriptions are the exception and are not an estimate: see 18a.
- 18c (keep the single value in slot 2, widen the row gap to 28px) is rejected: it cures the crowding but moves the value's left edge by exercise type, so a mixed session shuffles sideways.
- Removing an added exercise you changed your mind about. Resolved in 34/35: lives in the Reorder screen, and ONLY on rows added this session. A program exercise you will not do is a skip, and skipping has no verb (22a), so remove on a program row would be the skip verb sneaking back in. Styled per 35b: no visible control at rest, rows stay handle + name (+ Added tag, the only mark of removability). A leftward swipe reveals Remove in dusty red #B25753, the same muted register as the two hues, so the third hue exists only mid-gesture and never unprompted. Horizontal swipe does not fight the vertical drag. 35a (permanent iOS red minus disc) and 35c (in-palette Remove pill, tap to arm) rejected.
- Grouping added exercises into a superset during the session. Raised in 28 and not drawn: it is a different interaction from picking one exercise (pick two, then declare the pairing).
- Exercise page (progression over time, recent sessions, resources such as YouTube links and URLs). Owned by the progress screen workflow, reached from there by tapping an exercise, and also reached from logging via the rail's Detail. Design it once, in that context, so both entries land on the same page. Open when we get there: whether it changes what it leads with depending on which entry you came through.
- Add-exercise picker flow.
- 21c (target RPE top right) is rejected: cleanest at rest and worst under load, because rest owns that corner. The countdown would evict the target for the whole two minutes after every set, and the swapped card has to ellipsise the exercise name to keep an 11px target on the row.
- 22b (Skip in the rail) is rejected: it takes the rail to four items when it was already at its limit, and it turns skipping into a commitment you declare in the moment, standing in front of a machine you might come back to. The app has no "not now" verb and Skip would quietly become one.

### Platform / engineering notes

- **Dynamic Type pass** (deferred, whole screen): every size in these mocks is fixed px at the iOS default. The subheader lines are not the binding constraint, since both 21a and 21d wrap at large type and 21d wraps into 21a, so the placement choice holds at any size. The real constraint is the four slot set table: 30 + 76 + 76 + 44 plus four 12px gaps is 274px of fixed columns inside 356px of card, so it tolerates moderate scaling and breaks at the accessibility sizes, where it will need to reflow rather than shrink. Worth its own pass once the statics are locked; not a reason to choose differently now.

- **Live rest timer outside the app** (user request, high value): when the phone locks or the app backgrounds, the rest countdown should keep ticking on the lock screen / home screen as a live workout-in-progress event — not an Apple timer — tappable to jump back into the session. Needed because a 2:00 rest outlives the default screen-sleep.
